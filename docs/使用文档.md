## 1. 快速开始

```bash
# 1. 克隆仓库
git clone <repository-url>
cd polymarket-copy-trading-bot

# 2. 安装依赖
npm install

# 3. 复制配置文件
cp .env.example .env

# 4. 编辑配置（填入钱包和 MongoDB 信息）
nano .env

# 5. 设置代币授权
npm run set-token-allowance

# 6. 启动机器人
npm run dev
```

### 5.4 跟单策略配置

| 变量名 | 默认值 | 类型 | 说明 |
|--------|--------|------|------|
| `COPY_STRATEGY` | `PERCENTAGE` | string | 跟单策略类型 |
| `COPY_SIZE` | `10.0` | 浮点数 | 主参数（含义依策略而定，见下文）|

**`COPY_STRATEGY` 三种模式：**

| 策略值 | `COPY_SIZE` 含义 | 适合场景 |
|--------|-----------------|---------|
| `PERCENTAGE` | 跟单被跟对象订单金额的百分比（%）| 新手首选，风险自动比例控制 |
| `FIXED` | 每笔交易固定金额（美元）| 预算固定，支出可预期 |
| `ADAPTIVE` | 基础百分比，自动根据订单大小调整 | 进阶用户，大单降比例/小单提比例 |

**示例：**

```env
# 跟单被跟对象每笔交易金额的 10%
COPY_STRATEGY = 'PERCENTAGE'
COPY_SIZE = 10.0

# 每笔固定跟单 $50
COPY_STRATEGY = 'FIXED'
COPY_SIZE = 50.0
```

### 5.6 高级跟单参数

#### 自适应策略参数（`COPY_STRATEGY = 'ADAPTIVE'` 时有效）

| 变量名 | 默认值 | 说明 |
|--------|--------|------|
| `ADAPTIVE_MIN_PERCENT` | `5.0` | 大单跟单最低百分比（%）|
| `ADAPTIVE_MAX_PERCENT` | `20.0` | 小单跟单最高百分比（%）|
| `ADAPTIVE_THRESHOLD_USD` | `500.0` | 分界阈值（美元）；超过此值的订单用低比例 |

**工作逻辑：**

```
被跟单者下单 $100（< $500 阈值）→ 用最高比例 20% → 跟单 $20
被跟单者下单 $1000（> $500 阈值）→ 用最低比例 5% → 跟单 $50
```

#### 分档乘数（`TIERED_MULTIPLIERS`）

按订单金额区间设置不同的乘数：

```env
# 格式：最小值-最大值:乘数,最小值-最大值:乘数,...
TIERED_MULTIPLIERS = '1-10:2.0,10-100:1.0,100-500:0.2,500+:0.1'
```

| 订单范围 | 乘数 | 实际效果（COPY_SIZE=10%）|
|----------|------|-------------------------|
| $1 - $10 | 2.0x | 跟单 20% |
| $10 - $100 | 1.0x | 跟单 10% |
| $100 - $500 | 0.2x | 跟单 2% |
| $500+ | 0.1x | 跟单 1% |

#### 旧版参数（已弃用，仅兼容保留）

```env
# 已弃用，请迁移到 COPY_STRATEGY 系统
# COPY_PERCENTAGE = 10.0
# TRADE_MULTIPLIER = 1.0
```

### 5.9 做市商策略配置

> 仅在 `BOT_MODE = MARKET_MAKING` 或 `BOT_MODE = HYBRID` 时生效。

基于论文 [arxiv 2510.15205](https://arxiv.org/abs/2510.15205)（Logit 跳跃扩散模型）实现的自动做市商策略。

#### 核心资金配置

| 变量名 | 默认值 | 类型 | 说明 |
|--------|--------|------|------|
| `MM_BASE_CAPITAL` | `10000` | 浮点数（美元）| 部署到所有市场的总资金 |
| `MM_ORDER_SIZE_USD` | `100` | 浮点数（美元）| 每个限价单的金额（买/卖各一单）|
| `MM_MAX_INVENTORY_PER_MARKET` | `500` | 浮点数（美元）| 单个市场最大净持仓 |
| `MM_MAX_TOTAL_INVENTORY` | `3000` | 浮点数（美元）| 所有市场总最大持仓 |
| `MM_MARKET_LIMIT` | `20` | 整数 | 同时做市的最大市场数量 |
| `MM_REBALANCE_INTERVAL` | `30` | 整数（秒）| 刷新报价的频率 |

**$100 小资金配置示例：**

```env
MM_BASE_CAPITAL = 100
MM_ORDER_SIZE_USD = 1
MM_MAX_INVENTORY_PER_MARKET = 5
MM_MAX_TOTAL_INVENTORY = 100
MM_MARKET_LIMIT = 20
```

#### 价差设置

| 变量名 | 默认值 | 说明 |
|--------|--------|------|
| `MM_BASE_SPREAD` | `0.02` | NORMAL 波动率区间下的基础买卖价差（0.02 = 2 美分）|
| `MM_CALM_SPREAD` | `0.01` | CALM 区间（σ < 0.02）的收窄价差（1 美分）|
| `MM_MAX_SPREAD` | `0.08` | 价差上限（8 美分）|
| `MM_REPRICE_THRESHOLD` | `0.005` | 触发重新报价的最小价格变动（0.5 美分）|
| `MM_POST_ONLY` | `true` | 纯被动模式：若订单会成为吃单则拒绝 |

**价差与波动率的关系：**

```
σ_total < 0.02  → CALM   → 使用 MM_CALM_SPREAD (1¢)
σ_total < 0.06  → NORMAL → 使用 MM_BASE_SPREAD (2¢)
σ_total < 0.10  → VOLATILE → 自动加宽
σ_total ≥ 0.10  → EXTREME → 停止报价，撤单
```

#### 风险系数（论文参数）

| 变量名 | 默认值 | 符号 | 说明 |
|--------|--------|------|------|
| `MM_RISK_AVERSION` | `0.2` | γ（伽马）| 库存风险厌恶系数；值越大，持仓时价差越宽 |
| `MM_VOL_SENSITIVITY` | `1.0` | β（贝塔）| 信念波动率敏感度；值越大，高波动时价差越宽 |
| `MM_JUMP_SENSITIVITY` | `0.5` | ζ（泽塔）| 跳跃强度敏感度；值越大，高跳跃频率时价差越宽 |
| `MM_CALENDAR_FACTOR` | `2.0` | — | 临近结算时的价差放大倍数 |

**参数调优指引：**

| 目标 | 调整方向 |
|------|---------|
| 减少持仓风险 | 提高 `MM_RISK_AVERSION`（建议 0.3-0.5）|
| 高波动市场更保守 | 提高 `MM_VOL_SENSITIVITY`（建议 1.5-2.0）|
| 跳跃市场更保守 | 提高 `MM_JUMP_SENSITIVITY`（建议 0.8-1.0）|
| 更激进赚取价差 | 降低三个系数（风险上升）|

#### 市场筛选条件

| 变量名 | 默认值 | 说明 |
|--------|--------|------|
| `MM_PRICE_RANGE_MIN` | `0.10` | 仅做市价格 ≥ 10% 的市场（排除几乎确定的结果）|
| `MM_PRICE_RANGE_MAX` | `0.90` | 仅做市价格 ≤ 90% 的市场（排除几乎确定的结果）|
| `MM_MIN_MARKET_AGE_DAYS` | `14` | 仅做市至少开放 14 天的市场（有足够历史数据）|
| `MM_MIN_DAYS_TO_RESOLUTION` | `7` | 距离结算不足 7 天时停止做市 |
| `MM_MAX_SIGMA` | `0.07` | 总波动率 σ_total 硬截断（超过则跳过该市场）|

**筛选逻辑示意：**

```
市场价格 ∈ [0.10, 0.90]  ✓
市场年龄 ≥ 14 天           ✓
剩余天数 ≥ 7 天            ✓
σ_total < 0.07            ✓
→ 允许做市
```

#### 趋势检测与风险管理

| 变量名 | 默认值 | 说明 |
|--------|--------|------|
| `MM_TREND_THRESHOLD` | `0.3` | 趋势信号阈值（0-1）；超过此值时激活单边报价模式 |
| `MM_MAX_DAILY_LOSS` | `200` | 单个市场每日最大亏损（美元）；超过则暂停该市场 24 小时 |

#### EM 算法参数（跳跃扩散模型估计）

| 变量名 | 默认值 | 说明 |
|--------|--------|------|
| `MM_PRICE_HISTORY_WINDOW_HOURS` | `168` | 喂入 EM 算法的历史价格窗口（168 = 7 天）|
| `MM_EM_MAX_ITERATIONS` | `50` | EM 算法最大迭代次数 |

> **技术说明**：做市策略使用混合 EM 算法估计跳跃扩散参数（σ_D、λ、σ_J），并计算总波动率：
> ```
> σ_total = √(σ_D² + λ × σ_J²)
> ```
> 其中 σ_D 为扩散波动率，λ 为跳跃频率，σ_J 为跳跃幅度。该指标用于区间分类和价差门控。

## 6. 运行模式说明

通过 `BOT_MODE` 变量选择运行模式：

### COPY 模式（默认）

```env
BOT_MODE = COPY
```

监控指定交易者的买卖操作，按比例自动跟单。适合无需自行判断市场的用户。

**数据流：**
```
监控 USER_ADDRESSES 的交易 → 计算跟单金额 → 在相同市场下单
```

### MARKET_MAKING 模式

```env
BOT_MODE = MARKET_MAKING
```

自动在 Polymarket 上做市（同时挂买单和卖单），通过价差和流动性奖励赚取收益。

**数据流：**
```
扫描活跃市场 → 筛选符合条件的市场 → 估计跳跃扩散参数 →
计算最优报价 → 挂买单/卖单 → 定期刷新报价
```

### HYBRID 模式

```env
BOT_MODE = HYBRID
```

同时运行跟单和做市两套策略，充分利用资金。适合有足够资金且熟悉两种策略的进阶用户。

## 7. 跟单策略详解

### PERCENTAGE 策略（推荐新手）

```env
COPY_STRATEGY = 'PERCENTAGE'
COPY_SIZE = 10.0       # 跟 10%
MAX_ORDER_SIZE_USD = 100.0
MIN_ORDER_SIZE_USD = 1.0
```

**计算公式：**
```
跟单金额 = min(被跟交易金额 × COPY_SIZE%, MAX_ORDER_SIZE_USD)
         且 >= MIN_ORDER_SIZE_USD
```

**示例：** 被跟对象下单 $500，跟单 10% = $50（在限额内）

---

### FIXED 策略（固定支出）

```env
COPY_STRATEGY = 'FIXED'
COPY_SIZE = 25.0       # 每笔固定 $25
```

**特点：** 无论被跟对象下单多少，每笔都固定跟 $25（受 `MAX_ORDER_SIZE_USD` 约束）。

## 8. 做市商策略详解

### 工作流程

```
1. 每 MM_REBALANCE_INTERVAL 秒扫描符合条件的市场
2. 对每个市场：
   a. 获取最近 MM_PRICE_HISTORY_WINDOW_HOURS 小时的价格历史
   b. 运行混合 EM 算法估计 (σ_D, λ, σ_J) → 计算 σ_total
   c. 根据 σ_total 判断波动率区间（CALM/NORMAL/VOLATILE/EXTREME）
   d. EXTREME 区间 → 撤单，跳过
   e. 其他区间 → 计算最优买卖报价
   f. 挂出限价单（MM_POST_ONLY=true 确保只做被动成交）
3. 成交后更新库存，触发再平衡
```

### 收益来源

| 来源 | 占比（典型）| 说明 |
|------|------------|------|
| 流动性奖励 | ~75% | Polymarket 对做市商的奖励计划 |
| 逆向选择净收益 | ~23% | 正确预测价格方向的库存收益 |
| 价差捕获 | ~2% | 买卖价差直接收入 |

### 波动率区间说明

| 区间 | σ_total 范围 | 策略行为 |
|------|-------------|---------|
| CALM | < 0.02 | 使用最窄价差（MM_CALM_SPREAD），争取更多成交 |
| NORMAL | 0.02 - 0.06 | 使用标准价差（MM_BASE_SPREAD）|
| VOLATILE | 0.06 - 0.10 | 自动加宽价差，减少库存积累 |
| EXTREME | ≥ 0.10 或 > MM_MAX_SIGMA | 撤出全部订单，等待市场平稳 |

### 10.2 真实历史数据回测

**步骤 1：获取真实市场数据**

使用 Python 脚本从 Polymarket API 抓取数据：

```python
import requests, json

# 获取活跃市场
markets = requests.get(
    "https://gamma-api.polymarket.com/markets",
    params={"active": "true", "closed": "false", "_limit": 50,
            "liquidity_num_min": 5000}
).json()

data = []
for m in markets:
    token_ids = json.loads(m.get("clobTokenIds", "[]"))
    if not token_ids:
        continue
    # 获取价格历史（10分钟精度）
    history = requests.get(
        "https://clob.polymarket.com/prices-history",
        params={"market": token_ids[0], "interval": "max", "fidelity": 10}
    ).json().get("history", [])

    data.append({
        "conditionId": m["conditionId"],
        "question": m["question"],
        "token_yes": token_ids[0],
        "token_no": token_ids[1] if len(token_ids) > 1 else "",
        "startDate": m.get("createdAt", ""),
        "endDate": m.get("endDate", ""),
        "history": [{"t": h["t"], "p": h["p"]} for h in history]
    })

with open("/tmp/polymarket_data.json", "w") as f:
    json.dump(data, f)
print(f"已保存 {len(data)} 个市场")
```

**步骤 2：运行回测**


## 12. 故障排查

### 常见错误及解决方案

#### 启动报错：`Missing required environment variable`

```
原因：必填环境变量未设置
解决：检查 .env 文件，确保以下变量均有值：
  USER_ADDRESSES, PROXY_WALLET, PRIVATE_KEY,
  MONGO_URI, RPC_URL
```

#### 授权报错：`USDC allowance insufficient`

```
原因：未授权 USDC 或授权额度不足
解决：npm run set-token-allowance
```

#### 网络超时：`Request timeout after 10000ms`

```
原因：Polymarket API 响应慢或网络不稳定
解决：
  REQUEST_TIMEOUT_MS = 30000     # 增大超时时间
  NETWORK_RETRY_LIMIT = 5        # 增加重试次数
```

#### 做市商无法报价：`σ_total=0.001 CALM everywhere`

```
原因：旧版本 bug（已修复）
解决：确认代码版本包含 sigmaTotal 修复
  - 更新到最新版本
  - 确认 estimateParamsHybrid 返回 sigmaTotal 字段
```

#### MongoDB 连接失败：`MongoServerError: bad auth`

```
原因：MONGO_URI 用户名密码错误
解决：
  1. 登录 MongoDB Atlas 重置密码
  2. 更新 .env 中的 MONGO_URI
  3. 注意特殊字符需要 URL 编码（@ → %40）
```

### 日志级别调整

通过修改代码中 Logger 的输出级别可获得更多调试信息：

```bash
# 查看实时日志
npm run dev 2>&1 | tee bot.log

# 过滤做市相关日志
npm run dev 2>&1 | grep "\[MM"
```
